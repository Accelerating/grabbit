# 实施、部署与验收

## 1. 交接说明

先读 [技术设计](./technical-design.md) 和 [数据/API 契约](./data-and-api.md)。本轮只交付设计文档，不代表任何下载能力已实现。

现有仓库前后端均为模板，没有应保留的业务流程。实现时保留用户已有修改，不擅自清空目录。按阶段提供可验证的增量；每阶段说明完成内容、检查结果、尚存限制。不得用静态演示数据替代最终真实下载/进度/安装能力。

未指定的组件库细节、内部类名可自行决定；出现新的产品范围问题记录决策，不用反复询问已确认事项。必须遵守：无 Docker、低内存、独立两类下载、Cookie 独立页面、先解析视频、全局默认串行、默认浅色和双语、前端静态部署。

## 2. 分阶段实现

### 阶段 0：工程和契约

- 后端 Python 3.13 兼容范围、依赖锁文件、FastAPI 入口、配置加载、结构化脱敏日志、迁移。
- 前端关闭 SSR，路由、静态构建、API 客户端、语言/主题、登录壳、页面导航。
- 账号 CLI、会话/CSRF、路径校验、统一错误码；定义引擎适配接口和状态机。
- 发布脚本把前端 client 产物复制到后端 static；确保 VPS 不运行前端开发服务器。

验收：前端深链刷新可用，API/静态 404 正确，双语主题持久，创建管理员和登录/退出/改密可用；数据库升级不丢数据。

### 阶段 1：普通下载和可靠队列

- 专用 aria2 生命周期、检测、RPC、HTTP 下载、种子上传、磁力元数据、文件选择。
- SQLite 队列、并发控制、操作幂等、进度 SSE、全局排序、限速、失败重试、磁盘保护。
- 任务目录、历史和基本文件索引；正常停止和崩溃恢复。

验收：用本地可控 HTTP 服务和小型合法种子完成真实下载；并发 1 的普通任务串行，磁力内容不在用户选文件前启动；暂停/恢复/取消/重启都不重复建任务；完成后停止做种。

### 阶段 2：Cookie 和视频

- Cookie 独立页面、私有存储、站点默认、执行快照与引用保护。
- yt-dlp 独立进程、Deno/EJS、异步预解析、合集分页、格式/字幕选择、仅音频。
- 将视频和分析作业接入同一资源调度器；完整停止进程树；合并过程继续占槽。
- 字幕警告和单独重试、来源 URL 重新解析、日志脱敏。

验收：YouTube/B站单视频、B站多 P、YouTube 小型合集、音频、中英字幕场景；真实下载进度，音视频流均正确；缺字幕可成功；Cookie 失效可替换后重试。网络/IP 限制单独记录，不能把模拟测试算作站点实测。

### 阶段 3：文件、播放和界面完善

- 历史查询、文件浏览、独立播放页、Range、WebVTT、下载到浏览器。
- 删除预览和持久化操作、保留文件时删除记录、缺失文件标记。
- 任务详情、可操作错误、空状态、断网状态、手机布局、无障碍基础。

验收：较大 MP4 能拖动播放，音频可播，字幕切换可用；不支持编码有清楚提示；播放不会把整个文件读进内存；删除行为符合确认范围。

### 阶段 4：安装、部署和 768 MB 实测

- 依赖检测/安装界面、受限 root helper、工具版本环境、yt-dlp 更新/回退。
- systemd、Nginx HTTPS 配置模板、首次部署脚本、管理员 CLI 和运行说明。
- 低内存与磁盘不足故障注入、日志轮转、备份恢复、服务重启验证。

验收：干净 Debian 13 amd64 环境按文档可从零部署；网页安装真实可用，失败有日志；768 MB 配额下默认串行稳定执行典型下载，实测数据写入性能报告。必须交付测量证据或明确标注此项尚未验收。

## 3. 部署目录和运行方式

建议约定：

```text
/opt/grabbit/releases/<version>/     后端代码、静态资源、后端 .venv（root 管理）
/opt/grabbit/current                 当前发布目录链接（root 管理）
/etc/grabbit/grabbit.env             启动配置，root:grabbit 0640
/var/lib/grabbit/grabbit.db          SQLite 和 WAL
/var/lib/grabbit/private/cookies/    Cookie 原件与快照，0700
/var/lib/grabbit/private/torrents/   种子原件
/var/lib/grabbit/tools/              yt-dlp 版本 venv、Deno（grabbit 可写）
/var/lib/grabbit/cache/              解析、封面等有界缓存
/var/lib/grabbit/aria2/              私有 RPC 配置和会话
/var/lib/grabbit/logs/               引擎有界日志
/srv/grabbit/downloads/              下载根目录（grabbit 可写）
/usr/local/libexec/grabbit-install   root 拥有的受限 helper
/etc/sudoers.d/grabbit-install       精确动作授权
```

前端在本机/CI 构建后进入发布包；后端依赖在目标机从锁文件安装 venv，优先 wheel，不复制开发机的 venv。不得要求在 768 MB VPS 运行 Node 构建或编译 Python。

首次部署脚本（后续实现，不是本文已提供）负责：

1. 检测 Debian/架构/系统 Python；创建 grabbit 用户和目录，设置权限。
2. 安装 Python venv、CA 证书、sudo 等启动所需包；部署后端 venv 和配置。
3. 安装只允许两种固定动作的 helper 和 sudoers，并用 `visudo -cf` 验证。用户执行一次管理员配置后，网页可装 aria2/ffmpeg。
4. 执行迁移；通过交互式 CLI 创建管理员，密码不出现在命令参数、shell 历史或日志。
5. 安装 systemd unit，启动 Web；缺下载工具时仍可登录设置并安装。
6. 完整提供 Nginx 与 ACME HTTPS 配置步骤，域名/IP/邮箱使用占位符。未具备域名时可先通过 SSH 隧道 localhost 验证，正式公网使用 HTTPS。

建议 CLI 契约：

```text
python -m app.cli db upgrade
python -m app.cli admin create       # 交互读取账号与密码
python -m app.cli admin reset-password
python -m app.cli backup --output <受控备份目录>
python -m app.cli doctor             # 配置、权限、库、工具与 RPC 检查
```

## 4. systemd 与权限安排

基础 unit 要点：User/Group=grabbit、WorkingDirectory=/opt/grabbit/current/backend，加载固定 env；ExecStart 指定后端 venv 的 Uvicorn，`app.main:app --host 127.0.0.1 --port 8000 --workers 1`；不启用 reload。

使用 `Restart=on-failure`、合理 RestartSec/StartLimit、`KillMode=control-group`、`TimeoutStopSec=30`，让整个 yt-dlp/ffmpeg/aria2 进程树随服务退出；正常关闭应先停止调度、保存状态和 aria2 会话，再等待退出。UMask=0077；配置和代码只读，状态目录可写。

特别注意：同一服务若通过 sudo 调受限 helper，不能同时启用会阻断 sudo 的 `NoNewPrivileges=true`；也不能直接照搬禁止包管理器写系统目录的沙箱配置。首版选择“服务非 root + 精确 helper 授权”；如果改成独立特权安装 broker，需要另行完整实现认证和窄动作协议，不能只改 unit 让安装失效。

性能测试阶段先监控，不盲设很低的 MemoryMax；若生产加限制，必须把整个服务 cgroup 的子进程峰值计入，明确 OOM 会导致服务/任务失败及恢复行为。低内存阈值和单槽只能减少风险，不是内存硬隔离。

## 5. 反向代理、静态与流式响应

Nginx 反代到 127.0.0.1:8000，HTTPS 终止；后端仅信任来自本机代理的 forwarded headers。全站同源，不开放 aria2 RPC。

- `/api/v1/events`：关闭 proxy buffering/cache，设置 read timeout 至少 75 秒；后端 15 秒心跳。
- 上传整体上限建议 12 MiB，应用对 cookie 另限 1 MiB、种子 10 MiB；普通 JSON 最大 1 MiB。返回本地化的超限错误。
- `/api/v1/files/.../content`：保留 Range/If-Range/HEAD，关闭可能造成额外磁盘缓冲的代理缓存，不压缩视频。
- HTML 不长期缓存；hash assets 可一年 immutable。受保护文件不能由 Nginx 未鉴权 location 直接暴露。
- 正式 HTTPS cookie 设置 Secure；仅显式开发配置允许 localhost HTTP，不通过错误的转发头自动降级。

## 6. 工具健康检查与安装验收

| 项目 | 本机检查 | 业务验证 |
| --- | --- | --- |
| aria2 | executable/version + 专用 RPC getVersion | 小文件真实下载，暂停/恢复可用 |
| yt-dlp | 独立 venv 可执行、版本、所需依赖存在 | 指定公开测试视频解析/下载 |
| ffmpeg/ffprobe | 两个程序版本、短探测超时 | 小型双流合并，主流信息正确 |
| Deno/EJS | 运行时版本、匹配组件、受控 JS 自检 | YouTube 实际解析，不把 --version 当成功 |

默认检测不请求真实站点，避免耗时和 Cookie 意外泄露；真实站点验证由用户提交 URL 或验收脚本显式执行。依赖 UI 区分“本机可用”和“最近站点验证结果”。

安装作业不承诺零峰值内存：暂停新工作、等待引擎退出、检查剩余内存/磁盘，再执行。版本下载失败、校验失败或新版本检测失败应保留原版本；不得以失败安装覆盖可用环境。禁止 `curl | sh`，禁止接收用户任意包名/版本/命令。

## 7. 测试与验收矩阵

使用 pytest/asyncio 做后端核心行为测试，前端以类型检查、必要组件测试和 Playwright 主流程为主。常规 CI 用受控 fixture/fake engine，真实工具和站点作为单独集成验收，防止网络不稳定污染全部测试。不能只测试 mock 然后宣称完整验收。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 两类各排入 3 个任务，并发 1 | 全局最多 1 个任务执行；完成后按全局排序推进 |
| 视频合并期间提交新任务/解析 | 继续等待，不突破名额和重型槽 |
| 合集 500 项 | 分批解析/存储/展示，不一次在内存保留全部原始 JSON |
| HTTP 支持/不支持 Range 的来源 | 支持续传则恢复，不支持时合理重下并提示 |
| 磁力元数据产生内容 GID | 正确绑定同一任务，用户确认前不下载内容 |
| BT 完成 | 停止做种，上传归零；未选文件不标记完成产物 |
| 默认字幕策略 | 中英文人工优先，缺失时自动，无字幕仍成功 |
| 字幕请求失败 | 主媒体可完成并带警告，单独字幕重试不重新下载主媒体 |
| 音频模式 | 源格式输出，不产生隐式 MP3 转码 |
| Cookie 替换/删除 | 快照稳定，未来执行用新版，活动引用阻止删除 |
| 自动重试 | 最多初始 + 2 次；30/120 秒等待让出名额，手动停止可撤销 |
| 下载/合并中服务重启 | 无孤儿进程、无重复任务；有效文件不被覆盖，部分文件可重试 |
| 低磁盘/ENOSPC | 阻断、暂停/停止、保留临时文件、空间恢复不擅自启动 |
| 修改并发/限速 | 并发降低不强杀任务；yt-dlp 延迟生效明确可见 |
| SSE 断线/乱序/会话过期 | 进度重同步、旧 revision 不覆盖新状态、撤销后断开 |
| 大 MP4 拖动播放 | 正确 206/416，内存不随文件大小线性增长 |
| 不支持的容器/编码 | 提示下载文件，不偷偷服务器转码 |
| 仅删记录 | 文件仍在文件管理可见，可正常播放/下载 |
| 删除记录及文件中途失败/重启 | 操作可对账，展示部分失败，不误删其他目录 |
| 路径穿越/符号链接/恶意种子名 | 拒绝访问和写出下载根目录 |
| 未登录访问文件/字幕/SSE/Cookie | 全部被拒绝，无秘密泄露 |
| CSRF/登录暴力尝试 | 跨站写入被拒绝，登录限速且内存验证并发受控 |
| 全新 Debian 安装 | 无工具也能登录并检测，通过网页完成授权范围内安装 |
| 工具更新失败/apt 锁占用 | 保留原版本、明确错误，不破坏系统包管理器 |
| 主题与语言 | 登录页/所有页面完整双语，首次浅色，刷新保持用户选择 |
| 窄屏 390px | 新建、暂停/停止、Cookie 选择、播放无横向溢出且可点击 |

性能测试至少记录：系统/工具版本、是否 swap、cgroup memory.current/memory.peak、MemAvailable、CPU、下载/合并耗时、UI API 延迟、OOM/交换活动。工作负载包括空闲 15 分钟、普通大文件、1080p 双流视频、字幕、100 条解析摘要、浏览历史、下载时开两个页面。

目标：空闲服务 <=160 MiB，典型单任务峰值尽量 <=500 MiB；768 MiB 环境无 OOM，控制接口通常 1 秒内响应（不含远程解析/下载）。只测本机高内存电脑不足以通过此项。无法访问 VPS 时交付测量脚本和明确的“待目标环境验收”状态。

## 8. 备份、升级与运维交付

- 备份数据库（安全 backup 或停机）、配置、Cookie 私有文件、种子、工具版本清单；下载文件独立可选备份，不把大媒体默认塞进数据库备份。
- 更新应用前停止调度并正常停服务，备份后迁移，再原子切换发布目录；迁移失败不启动新版本。代码回滚前确认 schema 兼容，不盲目降级库。
- 文件不会自动清理；只清理过期解析、过期会话、过期幂等键、已退出尝试的 Cookie 快照和有界日志缓存。
- 诊断包必须脱敏；秘密目录不置于静态目录/下载目录，不提交到 Git。
- 文档补齐实际命令、env 示例、unit/helper/Nginx 文件的安装方法、数据位置、日志位置、备份恢复、密码重置、依赖故障处理。

最终交付应包含可构建代码、锁文件、迁移、测试、发布脚本、部署配置、README 操作说明和性能验证报告。没有完成的实测必须列为待验收，不用“理论可用”代替结果。
